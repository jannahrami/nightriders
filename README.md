# NightRiders — دليل الإعداد والتشغيل

تطبيق ويب (PWA) خاص بمجموعة بايكرية. الواجهة مكتوبة بـ HTML وCSS وJavaScript بدون أدوات بناء، والبيانات على Supabase. الحماية كلها داخل قاعدة البيانات عبر سياسات RLS، وليست بإخفاء الأزرار.

> **حالة التسليم:** الملفات كاملة وجاهزة. التشغيل الفعلي ينتظر ربطها بمشروع Supabase الخاص بك، لأني لم أحصل على بيانات ربط. اختبرت قاعدة البيانات والصلاحيات على PostgreSQL 16 حقيقي مع محاكاة لأجزاء Supabase، واختبرت الواجهة في متصفح Chromium بوضع المعاينة. التفاصيل في قسم «نتائج الاختبار».

## 1) إنشاء مشروع Supabase وتشغيل ملف SQL

1. أنشئ مشروعًا جديدًا في [supabase.com](https://supabase.com). يفضّل اختيار منطقة قريبة، مثل Frankfurt أو Mumbai.
2. من لوحة المشروع افتح **SQL Editor**، ثم **New query**.
3. الصق محتوى الملف `supabase/schema.sql` كاملًا واضغط **Run**.

ينشئ هذا الملف:

- الجداول: الأعضاء، الدعوات، الطلعات، المحطات، المشاركة، التصويت، الرسائل، المواقع، طلبات المساعدة، الوسائط، الإعلانات.
- سياسات RLS لكل جدول.
- الدوال الإدارية.
- حاوية تخزين خاصة باسم `nightriders`.
- تفعيل التحديث المباشر (Realtime) للجداول المطلوبة.

الملف آمن لإعادة التشغيل عند التحديث.

> **اختياري:** لتنظيف المواقع المنتهية من القاعدة كل 5 دقائق، فعّل إضافة `pg_cron` من Database ← Extensions، ثم شغّل السطر الموجود في آخر الملف. المواقع المنتهية تختفي عن الأعضاء فورًا حتى بدون هذه الخطوة، لأن السياسات تخفيها، وتُحذف عند أول تحديث موقع لأي عضو.

## 2) ملف الإعدادات: أين تضع العنوان والمفتاح

1. انسخ `config.example.js` باسم `config.js` في نفس المجلد.
2. من Supabase افتح **Project Settings ← API** (أو **API Keys**)، وانسخ:
   - **Project URL** وضعه في `supabaseUrl`.
   - **anon public** (أو **publishable**) key وضعه في `supabaseAnonKey`.

```js
window.NR_CONFIG = {
  supabaseUrl: 'https://abcdefghijk.supabase.co',
  supabaseAnonKey: 'eyJhbGciOi...',
  ...
};
```

> ⚠️ **لا تضع مفتاح `service_role` أبدًا.** التطبيق يرفض العمل إذا اكتشفه ويعرض تحذيرًا. المفتاح العام آمن في الواجهة، لأن كل الصلاحيات محمية في قاعدة البيانات.

## 3) إعداد المصادقة في Supabase

افتح **Authentication ← URL Configuration**:

- **Site URL**: ضع رابط موقعك النهائي، مثل `https://nightriders.netlify.app`.
- **Redirect URLs**: أضف الرابط نفسه، وأضف `http://localhost:8080` إذا كنت ستجرب محليًا.

افتح **Authentication ← Providers ← Email**:

- اترك **Confirm email** مفعّلًا (موصى به).
- خدمة البريد المدمجة في Supabase محدودة جدًا، ترسل رسائل قليلة في الساعة. للاستخدام الفعلي أضف SMTP خاصًا من **Authentication ← SMTP Settings**، مثل Resend أو Brevo أو Gmail SMTP. بديل ذلك إيقاف تأكيد البريد، وحينها يدخل العضو مباشرة بعد التسجيل ويبقى بانتظار موافقتك.

> **ملاحظة:** أي شخص يستطيع إنشاء حساب مصادقة من صفحة التسجيل، لكنه لا يرى أي شيء. لا يُنشأ له ملف في القروب إلا بكود دعوة صالح، ثم يبقى «بانتظار الموافقة» حتى تقبله. هذا مُختبر في القسم 3 من الاختبارات.

## 4) إعداد الأدمن الأول بطريقة آمنة

حسابك الأول لا يحتاج كود دعوة. يُعيَّن من داخل Supabase فقط:

1. من **Authentication ← Users** اضغط **Add user ← Create new user**، وأدخل بريدك وكلمة مرور، وفعّل **Auto Confirm User**.
2. من **SQL Editor** شغّل:
   ```sql
   select public.bootstrap_owner('بريدك@example.com', 'اسمك في القروب');
   ```
3. افتح التطبيق وسجّل الدخول بنفس البريد وكلمة المرور.

**لماذا هذه الطريقة آمنة:**

- دالة `bootstrap_owner` مسحوبة الصلاحية من جميع الأدوار العامة (`anon` و`authenticated` و`service_role`)، فلا تعمل إلا من SQL Editor.
- تعمل مرة واحدة فقط. إذا وُجد أدمن أساسي ترفض التنفيذ.
- قاعدة البيانات تمنع وجود أكثر من أدمن أساسي واحد.
- لا يستطيع أي مستخدم تغيير دوره أو حالته بنفسه. هذا ممنوع بصلاحيات الأعمدة وبـ trigger داخل القاعدة معًا، ومُختبر.

## 5) التشغيل محليًا

يجب تشغيل التطبيق عبر خادم ويب، ولا يعمل بفتح الملف مباشرة. استخدم أحد الأمرين من داخل مجلد المشروع:

```bash
python3 -m http.server 8080
# أو
npx serve -l 8080 .
```

ثم افتح `http://localhost:8080`.

- **الموقع والكاميرا:** المتصفح لا يسمح بهما إلا على `localhost` أو عبر HTTPS. لتجربة الموقع من الجوال انشر التطبيق على استضافة HTTPS (الخطوة التالية).
- **وضع المعاينة:** افتح `http://localhost:8080/?preview=1` لتصفح الواجهة ببيانات تجريبية بدون Supabase. يظهر شريط بنفسجي ثابت يوضح أنها بيانات غير حقيقية ولا تُحفظ، وتختفي عند إعادة التحميل. هذا الوضع مفصول تمامًا ولا يتصل بقاعدتك.

## 6) النشر على استضافة HTTPS

التطبيق ملفات ثابتة، ويعمل على أي استضافة ثابتة مجانية. تذكّر أن `config.js` يجب أن يُرفع مع الملفات. هو لا يحتوي أسرارًا، فقط العنوان والمفتاح العام.

**Netlify (الأسهل):**

1. ادخل [app.netlify.com/drop](https://app.netlify.com/drop).
2. اسحب مجلد `nightriders` كاملًا، ومعه `config.js`.
3. ستحصل على رابط `https://xxxx.netlify.app`. ضعه في Site URL وRedirect URLs في Supabase (الخطوة 3).

**بدائل:**

- **Cloudflare Pages:** Create project ← Direct Upload ← ارفع المجلد.
- **Vercel:** `npx vercel` من داخل المجلد.
- **GitHub Pages:** يعمل، لكن إذا كان المستودع عامًا فسيكون `config.js` مكشوفًا للجميع. هذا مقبول لأن المفتاح عام، لكن تأكد أنه ليس service_role.

**بعد كل تحديث للواجهة:** غيّر رقم `VERSION` في `sw.js` حتى تصل النسخة الجديدة للأجهزة المثبّت عليها التطبيق.

**الإضافة للشاشة الرئيسية:**

- **iPhone:** افتح الرابط في Safari ← زر المشاركة ← «إضافة إلى الشاشة الرئيسية».
- **Android:** من قائمة Chrome ← «تثبيت التطبيق».

## 7) إضافة عضو جديد (الدورة الكاملة)

1. **الأدمن:** حسابي ← لوحة الأدمن ← الدعوات ← «إنشاء دعوة جديدة». تختار المدة (يوم، 3 أيام، أسبوع) وعدد مرات الاستخدام.
2. شارك الرابط أو الكود مع العضو عبر زر المشاركة أو واتساب. الرابط يفتح صفحة التسجيل والكود معبأ.
3. **العضو:** يسجّل بالكود واسمه وبريده، فيصبح «بانتظار الموافقة» ولا يرى شيئًا.
4. **الأدمن:** لوحة الأدمن ← طلبات الانضمام ← «قبول». ينتقل العضو تلقائيًا للتطبيق إذا كانت صفحته مفتوحة.
5. **لتعيين أدمن إضافي:** لوحة الأدمن ← الأعضاء ← «…» ← «تعيين أدمن». هذا متاح للأدمن الأساسي فقط.

## ما يعمل فعليًا، وما يحتاج خدمة خارجية

### يعمل بالكامل مع Supabase وحده (بعد الإعداد أعلاه)

| الميزة | التفاصيل |
|---|---|
| الدعوات والعضوية | دعوات محددة المدة وعدد الاستخدام، إلغاء الدعوة، قبول ورفض وإيقاف وإعادة تفعيل، أدمن إضافي بصلاحية الأساسي فقط |
| الحماية | RLS على كل الجداول والتخزين. الإيقاف يمنع الوصول فورًا للبيانات والملفات والتحديثات المباشرة الجديدة |
| الصفحة الرئيسية | الطلعة القادمة، المشاركون، «جاهز أطلع»، الإعلانات المثبتة، طلبات المساعدة، الاختصارات. كلها من البيانات الفعلية |
| ملف البايكر | الاسم، الصورة، المدينة، الدباب، الموديل، صورته، أسلوب الركوب، رقم اختياري مع التحكم بإظهاره (المخفي لا يراه حتى الأدمن) |
| جاهز أطلع | ساعة أو ساعتين أو 4 ساعات، وتنتهي تلقائيًا (بحد أقصى 12 ساعة تفرضه القاعدة) |
| الشات | عام، ولكل طلعة شات مستقل، نص وصور مضغوطة، تحديث مباشر، تحميل تدريجي، حذف رسائلك، حذف الأدمن، حالة إرسال وفشل وإعادة محاولة، منع التكرار بمعرّف فريد لكل رسالة |
| الطلعات | إنشاء وتعديل، مواعيد التجمع والتحرك والعودة، نقاط على الخريطة، محطات بنزين واستراحات، قائد وآخر ركب من المشاركين المؤكدين فقط، الحالات الأربع، فتح النقاط في Apple Maps أو Google Maps أو Waze |
| المشاركة ومتابعة الحالة | مشارك / يمكن / معتذر، ثم «في الطريق» و«وصلت التجمع» و«رجعت بالسلامة» مع وقت التحديث من الخادم |
| التصويت | على الوجهة أو الموعد أو غيره، صوت واحد لكل عضو تفرضه القاعدة، تغيير الصوت أو سحبه، الإغلاق |
| مشاركة الموقع | متوقفة افتراضيًا، موافقة صريحة ثم إذن الجهاز، مدة محددة أو طوال الطلعة، زر إيقاف ظاهر، انتهاء تلقائي، آخر موقع فقط بلا سجل، تمييز الموقع الحديث من القديم، تنبيه واضح عن توقف التحديث في الخلفية |
| طلب المساعدة | الأنواع الأربعة، وصف، موقع بموافقة، «سأتواصل معه»، «تم الحل»، أرقام الطوارئ 911 و997، ولا يدّعي إرسال إشعارات |
| الألبوم | صور تُضغط قبل الرفع، ومقاطع حتى 50MB، تخزين خاص وروابط مؤقتة، حذف ملفاتك، الأدمن يدير الكل |
| لوحة الأدمن | العضويات، الدعوات، الإعلانات، الطلعات |
| الاتصال | شريط واضح عند انقطاع الإنترنت أو توقف التحديث المباشر، وتحديث البيانات تلقائيًا عند عودة الاتصال |
| PWA | قابل للتثبيت، أيقونات iPhone وAndroid، يفتح بسرعة من الذاكرة |

### يعتمد على خدمات خارجية مجانية (بدون حساب)

| الخدمة | الاستخدام | ملاحظة |
|---|---|---|
| **OSRM** (`router.project-osrm.org`) | حساب المسار والمسافة التقديرية | خادم تجريبي عام بلا ضمان. إذا فشل يحفظ التطبيق الطلعة ويعرض النقاط فقط بدون أي خط مستقيم. يمكنك تعطيله بوضع `routingUrl: ''` أو استبداله بخادم خاص |
| **CARTO / OpenStreetMap** | صور الخريطة الداكنة | مجاني للاستخدام المحدود مع ذكر المصدر (مذكور على الخريطة) |
| **jsDelivr / unpkg** | تحميل مكتبتي Supabase وLeaflet | يلزم اتصال بالإنترنت عند أول فتح |
| **Google Fonts** | خط IBM Plex Sans Arabic | عند تعذره يُستخدم خط الجهاز |

### غير موجود في هذه النسخة (يحتاج إعدادًا إضافيًا لاحقًا)

- **إشعارات فورية على الجوال (Push):** غير مفعّلة. طلبات المساعدة والرسائل تظهر داخل التطبيق فقط لمن يفتحه، مع تنبيه لمن التطبيق مفتوح عنده. التطبيق يقول هذا صراحة للمستخدم. تفعيلها يحتاج Web Push مع مفاتيح VAPID وEdge Function. iPhone يدعمها فقط للتطبيق المثبّت على الشاشة الرئيسية (iOS 16.4 فأحدث).
- **تتبع الموقع في الخلفية:** غير ممكن من تطبيق ويب. التحديث يتوقف غالبًا عند قفل الجوال أو الخروج من التطبيق، والتطبيق يوضح ذلك ويعرض الموقع كـ«قديم».
- **ضغط الفيديو:** المقاطع تُرفع كما هي (حتى 50MB).

## نتائج الاختبار

### أ) الصلاحيات وقاعدة البيانات — **180 اختبارًا: 180 ناجح، 0 فاشل**

**طريقة الاختبار:** شغّلت `schema.sql` نفسه على **PostgreSQL 16** حقيقي. أضفت قبله ملف `tests/supabase_mock.sql`، الذي يحاكي من Supabase:

- الأدوار `anon` و`authenticated` و`service_role`.
- الدالة `auth.uid()`.
- جدول `auth.users`.
- جداول التخزين.
- الصلاحيات الافتراضية الواسعة التي يمنحها Supabase لكل جدول جديد، حتى أتأكد أن الملف يسحبها فعلًا.

كل اختبار يُنفَّذ بهوية مستخدم حقيقية عبر `SET ROLE` ورمز JWT محاكى. الحسابات المستخدمة:

- **owner:** الأدمن الأساسي.
- **admin2:** أدمن إضافي.
- **m1** و**m2:** عضوان.
- **pending:** حساب غير مقبول.
- **outsider:** حساب بلا دعوة.
- **anon:** زائر غير مسجّل.

| القسم | النتيجة | أبرز ما تم التحقق منه |
|---|---|---|
| 1. إعداد الأدمن الأساسي | 4/4 | العضو والزائر لا يستطيعان تنفيذ `bootstrap_owner`. لا يمكن تعيين أساسي ثانٍ |
| 2. الدعوات | 16/16 | غير الأدمن لا يرى ولا ينشئ الدعوات. الكود الخاطئ والملغى والمنتهي تُرفض. دعوة الاستخدام الواحد لا تُستخدم مرتين. الزائر ممنوع من كل الجداول |
| 3. حساب غير مقبول | 10/10 | يرى ملفه فقط. لا يغيّر حالته ولا دوره. لا ينشئ ملفًا مباشرة. لا يوافق على نفسه |
| 4. الأدوار والترقية | 13/13 | العضو لا يرقّي نفسه ولا يعدّل ملف غيره. الأدمن الإضافي لا يعيّن أدمن ولا يوقف الأساسي. حد 12 ساعة لـ«جاهز أطلع» |
| 5. رقم التواصل | 9/9 | الرقم المخفي لا يراه أحد، ولا حتى الأدمن. يظهر فقط بعد التفعيل. غير المقبول لا يراه. لا يمكن الكتابة فوق رقم غيرك |
| 6. الطلعات والمشاركة | 27/27 | المنظّم يُضاف مشاركًا تلقائيًا. العضو لا يعيّن غيره منظّمًا. غير المنظّم لا يعدّل. قائد الطلعة من المؤكدين فقط، واعتذاره يلغي تعيينه. التوقيت من الخادم. غير المقبول لا يرى ولا يشارك |
| 7. التصويت | 16/16 | صوت واحد لكل عضو حتى مع التغيير. الإدراج المباشر للتحايل ممنوع. خيار من تصويت آخر مرفوض. لا تصويت بعد الإغلاق. غير المقبول لا يرى ولا يصوّت |
| 8. الشات | 17/17 | الضغط المزدوج (نفس المعرّف) لا يكرر الرسالة. لا إرسال باسم غيرك ولا تزوير الوقت. لا تعديل. حذف رسالتك فقط، والأدمن يحذف المخالف. غير المقبول ومن بلا عضوية لا يرون شيئًا |
| 9. مشاركة الموقع | 23/23 | لا إدراج مباشر. حد 12 ساعة. صف واحد لكل عضو (لا سجل). الإيقاف يخفي فورًا. **انتهاء المدة يخفي الموقع فورًا ثم يُحذف من القاعدة**. إنهاء الطلعة يحذف مواقعها |
| 10. طلب المساعدة | 8/8 | طلب مفتوح واحد لكل عضو. «سأتواصل معه». الحل من المتواصل. لا تعديل مباشر. غير المقبول لا يرى |

### ج) على مشروع Supabase الحقيقي (NightRiders — فرانكفورت)

طبّقت `schema.sql` على المشروع الفعلي، ثم شغّلت نفس الـ 180 اختبارًا داخل معاملة واحدة أُلغيت بالكامل في النهاية. تأكدت بعدها أن القاعدة فارغة ولا يوجد أي مستخدم أو بيانات تجريبية.

- **النتيجة: 179 من 180.**
- الاختبار الوحيد الذي لم يمر هو «m2 لا يحذف ملف m1» على مستوى SQL. السبب ليس ثغرة: Supabase نفسه يمنع أي حذف مباشر من جداول التخزين عبر SQL، ويفرض الحذف عبر Storage API. التطبيق يحذف عبر Storage API، وهناك تُطبَّق سياسة الحذف الخاصة بنا. هذا المسار لم أختبره فعليًا بعد.
- فحص الأمان في Supabase لم يُظهر أي جدول بلا RLS. التنبيهات الظاهرة تخص دوال `SECURITY DEFINER` المتاحة للمسجلين، وهذا مقصود: كل دالة تتحقق من الصلاحية بنفسها، ومُختبرة.

### ما **لم** أختبره (بصراحة)

- **الاتصال بمشروع Supabase حقيقي:** لم تتوفر بيانات ربط. يشمل ذلك التسجيل والدخول الفعلي، وإرسال البريد، وطلبات REST الحقيقية، و**Realtime** الحقيقي، ورفع الملفات إلى **Storage**. سياسات التخزين والتحديث المباشر مختبرة على مستوى قاعدة البيانات فقط.
- **الخريطة الفعلية (Leaflet) وخدمة OSRM:** بيئة الاختبار لم تستطع الوصول لهذه الخدمات الخارجية. تحققت فقط من أن التطبيق يعرض رسالة بديلة واضحة عند تعذر تحميل الخريطة، ومن أن الطلعة تُحفظ بالنقاط فقط عند فشل حساب المسار.
- **جوال iPhone فعلي:** لم أختبر عليه. يشمل ذلك إذن الموقع في Safari، والتثبيت على الشاشة الرئيسية، وصور HEIC.
- **وقت انتهاء المشاركة من جهة الواجهة:** مؤقت الإيقاف التلقائي في المتصفح لم يُختبر بالانتظار الفعلي. انتهاء الظهور نفسه مضمون ومُختبر في القاعدة.

**أنصح بعد الربط بتجربة سريعة بأربعة حسابات** (أنت، عضوان، وحساب بدون قبول) على هذه النقاط:

1. تسجيل بكود دعوة.
2. الموافقة.
3. رسالة مع صورة في الشات، والتأكد أنها تصل مباشرة للجهاز الآخر.
4. تصويت.
5. مشاركة الموقع لمدة 30 دقيقة ثم إيقافها من جوال حقيقي.
6. إيقاف عضو، والتأكد أنه خرج من التطبيق.

## ملاحظات تقنية للمستقبل

- **التواريخ:** تُحفظ في القاعدة بصيغة `timestamptz` (UTC)، وتُعرض دائمًا بتوقيت `Asia/Riyadh`. حقول إدخال الوقت تُفسَّر بتوقيت السعودية (+03:00) بغض النظر عن إعداد الجهاز.
- **الروابط المؤقتة للملفات:** صالحة ساعة واحدة. العضو الموقوف لا يستطيع إنشاء روابط جديدة، لكن رابطًا فُتح قبل الإيقاف يبقى صالحًا حتى تنتهي ساعته.
- **أحداث الحذف في التحديث المباشر:** Supabase لا يطبّق عليها RLS، لكنها تحمل المعرّف فقط، بلا محتوى.
- **إضافة ميزة جديدة:** أضف الجدول وسياساته في `schema.sql`، ثم صفحة في `js/pages/`، ثم مسارًا في `ROUTES` داخل `js/app.js`، وأضف الملف لقائمة `SHELL` في `sw.js`.
- **نقل ملكية الأدمن الأساسي:** غير متاح من الواجهة عمدًا. عند الحاجة يُنفَّذ يدويًا من SQL Editor.

## الإشعارات (Web Push)

تصل للجوال حتى والتطبيق مقفول: طلعة جديدة، طلب فزعة، رسالة في الشات (العام، أو شات طلعة أنت مشارك فيها).
كل عضو يفعّلها من «حسابي ← الإشعارات» ويختار الأنواع. في iPhone تعمل فقط بعد إضافة التطبيق للشاشة الرئيسية (iOS 16.4+).

كيف تعمل: Trigger على `rides` و`help_requests` و`messages` يرسل الحدث عبر `pg_net` لدالة الحافة `notify`
(`supabase/functions/notify`)، والدالة تختار المستلمين بـ `push_targets` وترسل الإشعار المشفّر.

لتجهيز نسخة جديدة:
1. شغّل `schema.sql` (يشمل قسم 12).
2. أنشئ مفاتيح VAPID (زوج ECDSA P-256 بصيغة JWK) وسرًّا عشوائيًا، ثم في SQL Editor:
   `insert into private.app_secrets(key,value) values ('vapid','{"publicKey":{...},"privateKey":{...}}'), ('notify_secret','<سر عشوائي>'), ('contact','https://<رابط التطبيق>/'), ('notify_url','https://<project-ref>.supabase.co/functions/v1/notify');`
3. انشر الدالة `notify` بدون تحقق JWT (هي تتحقق من `x-nr-secret` بنفسها).
4. ضع المفتاح العام (raw, base64url) في `config.js` باسم `pushPublicKey`.
لا تضع المفتاح الخاص في الواجهة أو في Git أبدًا.
